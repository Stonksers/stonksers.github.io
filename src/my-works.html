Daily ZPIA Pipeline

ZPIA is a compiled dataset of historical track defects spotted by patrollers and whether the defects have been fixed. Everyday, there are two sets of data that make up the full ZPIA dataset: Morning and PDSS. My task was to clean and combine the two datasets and output the result to an SQL database. This task was to be fully done within the Microsoft Azure cloud environment, using an Azure Data Factory pipeline, Azure Synapse Analytics notebook and Data Warehouse, and Azure Data Lake Storage.

Flow of ZPIA Daily Pipeline

Working on this task while receiving training has allowed me to learn about the track infrastructure of the MRT lines and the overall maintenance process, which will be useful information for future tasks. I learnt and made use of relevant knowledge to complete this task, like how the overall ZPIA system operates and what is represented in the data. I also learnt and used various skills, like Python, PySpark, data engineering, and using various Azure services. As this is my first time using the Azure environment and the PySpark library, it is especially important to go into this task with the right attitude. To learn effectively, I had to be patient and take the time to understand the required tools for the task, as well as be meticulous about my work by thoroughly checking the code for errors or any faulty output. Knowledge of the data is important not only for this task, but also for future tasks that may make use of the pipeline output. As Python is the main programming language for all activities relating to data engineering in Synapse Analytics, mastery over Python and the PySpark library (Apache Spark, similar to Pandas) is important.

Enhancing Track Defect Object Detection Model

This task is still incomplete as of writing. The main objective is to enhance on an object detection model for track defects that was trained by a previous intern. Unlike object recognition, object detection tells us both what the object is (classification) and where in the image it is (localisation). However, in my lessons in TP, only object recognition was taught. Although the concepts do carry over, the added dimension of localisation in object detection models is still a hurdle I need to overcome. The detection model trained by the previous intern was trained using a YOLO (You Only Look Once) model, which uses bounding boxes to locate the object in the image. One major challenge will be the data labelling process, as the raw images are not labelled. The track images are collected by an Automatic Track Inspection (ATI) system, which captures images of the track through the entire rail network. As such, not only will there be a lot of images without defects, there may be more than one defect per image. Data from a defect list can be used to help with the filtering and labelling process, but the labelling still needs to be done manually. Research on other object detection models is still to be done to try to find a way to simplify the labelling process. This project is likely to be incorporated as my Major Project.
